# i18n and page metadata

UI strings resolve from a locale catalog, and every page renders Open
Graph / Twitter tags so a shared link gets a preview.

## Locale

Set `LOCALE` (default `en`; `pt` or `pt-BR` select Portuguese):

```bash
LOCALE=pt gleam run
```

`config.load()` parses it into `cfg.locale`, and a config helper resolves
strings:

```gleam
config.t(ctx.config, "app.home")   // "Início" with LOCALE=pt
```

`mastro/i18n` ships a small catalog. A missing key falls back to English,
then to the key itself, so a typo is visible but never crashes a render.

```gleam
import mastro/i18n

i18n.parse("pt-BR")        // Pt
i18n.t(i18n.Pt, "app.home") // "Início"
```

The kit's `locale-toggle` component (see [Views & Templates](views.md))
renders a link to switch locale; pass the href and label the app wants:

```gleam
kit.locale_toggle([#("href", "?locale=pt"), #("label", "PT")], element.none)
```

## Site metadata

`mastro/meta` builds a `Site` from the app name and `APP_URL`:

```gleam
config.site(ctx.config)   // meta.Site(name, url, description, image)
```

`og:image` defaults to `/static/og.png` and is made absolute against the
site URL, so with `APP_URL=https://app.test` it renders
`https://app.test/static/og.png`. Without `APP_URL`, `for_request` fills
the URL from the request host — good for development, a placeholder in
production (set `APP_URL` there; the boot gate already requires it).

Pages render the tags through the layout:

```gleam
content
|> root_layout.wrap_site("Home", req, config.site(ctx.config))
```

`wrap_site` adds `<meta property="og:*">` and `<meta name="twitter:*">`
alongside the CSRF meta tag. `root_layout.wrap(inner, title, req)` is the
same but derives the site from the request, for pages that do not pass one.

You can also get the tags as a string:

```gleam
meta.site_from("my_app", option.Some("https://app.test"))
|> meta.with_description("A Gleam web app")
|> meta.preview_html
```
